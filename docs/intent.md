# Intent

> 에이전트가 문서를 직접 탐색하지 않고도 작업 단위 컨텍스트를 안정적으로 받게 하는 프로젝트 의도를 정의한다.

## References

- [Plan](./plan.md) - 현재 단계와 실행 순서
- [Architecture](./architecture.md) - 시스템 경계와 모듈 책임
- [Glossary](./glossary.md) - 공통 용어 정의

## 문제

- 문서를 직접 탐색하는 방식은 토큰 낭비와 범위 이탈을 유발한다.
- 대화형 요약 기반 컨텍스트는 재현성이 낮아 검증이 어렵다.
- 작업 완료 후 기록 위치 라우팅이 반복 비용을 만든다.

## 목표

- Task ID 중심 MCP 호출로 작업 컨텍스트를 즉시 제공한다.
- 문서 파싱/슬라이싱/조립은 deterministic extraction으로 처리한다.
- 완료/이슈 상황에서 기록 위치(write target)를 표준화한다.

## 핵심 흐름

1. 에이전트는 대형 문서를 직접 읽지 않고 `task.pack`을 호출한다.
2. 서버는 Task 중심으로 필요한 섹션만 조립해 컨텍스트를 반환한다.
3. 완료 또는 변경 기록 시 `task.targets`로 기록 위치를 받는다.

## 성공 기준

- 동일 저장소 상태에서 동일 컨텍스트 결과를 재현한다.
- Task 중심 실행 범위를 문서로 일관되게 추적한다.
- 구현 이전 단계에서도 계획/검증 기준이 문서만으로 유지된다.
